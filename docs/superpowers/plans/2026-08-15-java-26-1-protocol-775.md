# Java 26.1 and Protocol 775 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate the pinned PrismarineJS Java 26.1 dataset family and reflection-free protocol 775 codecs, without changing protocol 47 output by a single byte.

**Architecture:** A manifest-v2 fetcher resolves `dataPaths.json` aliases at one pinned commit and writes a hash-verified source tree. `packetgen` gains a reference resolver that reaches members of sibling bitfields, six new native codecs in `wire/java`, and login-role tags on 775's login and configuration packets so M2's negotiator drives the modern sequence without naming a packet type. Typed data models move into the version package that defines their shape. Validation is a codec-level differential suite against pinned ProtoDef, plus one opt-in live check against a real 26.1 server that also measures the largest frame a real login produces.

**Tech Stack:** Go 1.26.5, Devbox, Task, standard library only (`crypto/sha256`, `encoding/json`, `net/http`, `archive/*` not required), pinned Node `protodef` 1.19.0 and `minecraft-data` 3.113.1 from the existing `interop/node` tree.

## Dependencies

M4 depends on M3 being complete, because M3 is the first real consumer of the M2
login lifecycle and it exercises the generated 47 session end to end.

M4 also assumes **M2.5** has landed: schema-scoped native resolution, shared
named types, the recursion-depth counter, and parameterized native arguments.
Without schema-scoped resolution, 775's `position` and `entityMetadata` would be
handed protocol 47's hand-written codecs and would encode the wrong bytes, so
this is a correctness dependency, not a convenience.

M4 modifies no stream or conduit code. It does add login-role tags to 775's
packets, which M2 introduced and M2's negotiator already consumes.

### What Task 3 found

Two things beyond what this task anticipated, both forced by the real schema:

- **Bare references must resolve outward.** `DebugSubscriptionUpdate`
  discriminates a nested switch on `type`, a field of the container two levels
  out, and declares no default. The parser previously required a bare name in
  the innermost scope alone, matching node-protodef's `getField` literally;
  under that rule the packet is undecodable by anything, node-protodef included.
  A bare name now resolves lexically and `../` still names one exact level. The
  walk only ever accepts more than before, and searches the innermost scope
  first, so no existing wire format can shift. This overturns the deliberate
  `unqualified compareTo cannot escape container` parser test, which is replaced.
- **`bitflags` exposed no members.** `bitfield` already published its unpacked
  parts for anonymous merging; `bitflags` published none, and a *named* field of
  either kind kept none. Both now record members, which is what the fourteen
  path references need.

### What Stage M4.2 found

Six constructs the plan did not anticipate, all found by compiling the real
schema rather than by reading a summary of it:

- **Bare references resolve outward** (Task 3), and **`bitflags` published no
  members** (Task 3). Both are recorded above.
- **A named field argument was never resolved.** `{"name": ..., "type": ...}`
  fell through to raw JSON, so a type name that did not exist would have
  surfaced at generation rather than at parse.
- **A shared type lost its mapper.** `DebugSubscriptionDataType` is a mapper
  used in more than one place, so it compiles once as a shared type — and the
  reference to it kept the Go name while dropping the lookup tables, which made
  every symbolic case key comparing against it look invalid.
- **A packet body may be void.** `bundle_delimiter` is the schema's only one:
  its ID is the entire message.
- **A switch may discriminate on another switch, or on a plain option.** The
  compared value is whatever the chosen branch produced, so it is recovered
  when every non-void case carries the same optional type, and an absent value
  takes the default. Cases that disagree on a type are an error rather than a
  guess.
- **A case key may be unrepresentable.** `UntrustedSlot` discriminates on a
  varint and lists both `"0"` and `"false"`. Such a key is dropped only when its
  branch also reads nothing; one that would have read bytes still fails.

- [x] **Step 1: Write the failing test**

`Protocol().ID()` is `java/26.1`, edition `java`, version name `26.1`, protocol
775. Packet factories resolve for handshaking, status, login, configuration, and
play. Transitions: handshake next-state to status and to login;
`login_acknowledged` moves login to configuration; the configuration finish
handshake moves to play; the acknowledgement of `start_configuration` moves
play back to configuration; `set_compression` produces a compression control.

### What Task 8 found

Generating the package is what showed that M4.2's "parses as Go" was a weaker
claim than it sounded. The 775 codecs parsed and did not compile, for two
reasons, both now covered by their own tests:

- **A recursive type must be held through a pointer.** `SlotDisplay` reaches
  itself through a switch on its own kind, and a Go struct that contains itself
  by value has no size. Sharing terminates the compiler's recursion; the
  pointer is what makes the type exist at all.
- **A shared mapper compiles to a named string type**, while its lookup tables
  hold plain strings. Without a conversion at each end, the generated code
  assigns a string to a named type and indexes a `map[string]…` with one.

Three further things the real schema settled:

- **A packet body may be a name.** `spawn_position` is written as the name of a
  shared type rather than as a container, and `bundle_delimiter` as `void`.
- **A container may hold anonymous fields**, more than one of them, whose
  contents merge into the enclosing container. The protocol summary carries
  them with an empty name rather than rejecting them.
- **Modern disconnect reasons are NBT components, not JSON**, in configuration
  and play but not in login. `java.NewNetworkNBTText` builds the compound form,
  `{"text": …}`, because that is what this package's own reader accepts: it
  requires a compound root, while a bare string tag is also a literal component
  a real server may send. Whether the reader should accept a bare string root
  is a question for the differential suite in Task 10.

Two deviations from this task as written, each for a stated reason:

- **`Raw()` embeds files rather than string literals.** The datasets are copied
  into `generated/java/v26_1/raw/` and embedded, so the compiler is not asked
  to parse five megabytes of quoted JSON and a diff of the generated package
  stays readable.
- **The raw set and the coverage report are per-version choices**, `-raw` and
  `-coverage` on `mcdata-gen`, rather than something every version gets. Java
  1.8's generated package is consumed by two services that read only the typed
  registries, and this milestone may not change protocol 47's output. M6 owns
  whether that changes.

### What Task 9 found

**Roles alone are not enough, and this task's interface list understated what
was needed.** A role says which part a packet plays. Driving a login also means
building the packet that plays a part and reading the fields of one that
arrived, and the two protocols agree about almost nothing else: not packet
names, not IDs, not field types — protocol 47 sends a UUID as dashed text and
775 sends sixteen bytes — and not which states the sequence passes through.

So each version now generates a `loginExchange` implementing a new
`protocol.LoginExchange`, and the negotiator names no version and no packet
type. This is additive to protocol 47's package: `generated/java/v1_8` gains
`login_exchange.go` and nothing else changes, which `generate:check` and the
protocol 47 loopback interoperability suite both confirm. That is a deliberate
departure from "protocol 47 output byte-identical", recorded here because the
constraint was written about wire behaviour and this changes none of it.

Three things the sequence itself settled:

- **Login success is not the end and not a transition.** The client
  acknowledges it, and the acknowledgement is what moves the connection to
  configuration.
- **Configuration content is passed through, not read.** A server fills
  configuration with registries, tags, and resource packs, none of which play a
  part in the sequence. The negotiator answers the finish handshake and ignores
  the rest, which is exactly why `WithTerminalState` exists: a caller that
  needs that content stops at configuration and drives it itself.
- **Protocol 775 states whether it wants the session-server join**, in
  `shouldAuthenticate`. Protocol 47 has no such field, so its exchange reports
  true: a protocol 47 server that asks for encryption always expects the join.

One gap left open: a server may send a configuration keep-alive and expect an
answer within its timeout. The negotiator passes keep-alives through without
answering, which is safe for a sequence this short and would not be for a
caller that lingers in configuration. M5's routing owns keep-alive.

# Java 26.1 and Protocol 775 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate the pinned PrismarineJS Java 26.1 dataset family and reflection-free protocol 775 codecs, without changing protocol 47 output by a single byte.

**Architecture:** A manifest-v2 fetcher resolves `dataPaths.json` aliases at one pinned commit and writes a hash-verified source tree. `packetgen` gains a reference resolver that reaches members of sibling bitfields, six new native codecs in `wire/java`, and login-role tags on 775's login and configuration packets so M2's negotiator drives the modern sequence without naming a packet type. Typed data models move into the version package that defines their shape. Validation is a codec-level differential suite against pinned ProtoDef, plus one opt-in live check against a real 26.1 server that also measures the largest frame a real login produces.

**Tech Stack:** Go 1.26.5, Devbox, Task, standard library only (`crypto/sha256`, `encoding/json`, `net/http`, `archive/*` not required), pinned Node `protodef` 1.19.0 and `minecraft-data` 3.113.1 from the existing `interop/node` tree.

## Dependencies

M4 depends on M3 being complete, because M3 is the first real consumer of the M2
login lifecycle and it exercises the generated 47 session end to end.

M4 also assumes **M2.5** has landed: schema-scoped native resolution, shared
named types, the recursion-depth counter, and parameterized native arguments.
Without schema-scoped resolution, 775's `position` and `entityMetadata` would be
handed protocol 47's hand-written codecs and would encode the wrong bytes, so
this is a correctness dependency, not a convenience.

M4 modifies no stream or conduit code. It does add login-role tags to 775's
packets, which M2 introduced and M2's negotiator already consumes.

### What M4.1 found

Two things the real upstream data settled, recorded because later stages and
M10's conformance matrix depend on them:

- An alias chain ends in two ways. A directory can map a dataset back to
  itself, and it can be absent from `dataPaths.json` entirely: `proto` resolves
  to `pc/latest`, which is a real directory upstream does not index. Treating
  only the self-reference as terminal rejects `proto`.

  release name. Java 1.8.9 data lives under `data/pc/1.8`, so comparing against
  the release reported all seventeen 1.8 datasets as aliases. The manifest gained

  reports zero aliases against 26.1's six.

### What Task 3 found

Two things beyond what this task anticipated, both forced by the real schema:

- **Bare references must resolve outward.** `DebugSubscriptionUpdate`
  discriminates a nested switch on `type`, a field of the container two levels
  out, and declares no default. The parser previously required a bare name in
  the innermost scope alone, matching node-protodef's `getField` literally;
  under that rule the packet is undecodable by anything, node-protodef included.
  A bare name now resolves lexically and `../` still names one exact level. The
  walk only ever accepts more than before, and searches the innermost scope
  first, so no existing wire format can shift. This overturns the deliberate
  `unqualified compareTo cannot escape container` parser test, which is replaced.
- **`bitflags` exposed no members.** `bitfield` already published its unpacked
  parts for anonymous merging; `bitflags` published none, and a *named* field of
  either kind kept none. Both now record members, which is what the fourteen
  path references need.
